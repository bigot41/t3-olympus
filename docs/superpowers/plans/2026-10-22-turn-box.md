# Task list, next-step box and New profile button: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude desktop's task list and next-step box in T3, pushed from T3's own socket instead of polled, plus a New profile button.

**Architecture:** The `olympus` MCP server (`wrapup_mcp.py`) gains `update_plan`, Claude desktop's rules, and system-prompt `instructions`. A hook inlined into T3's `index.html` wraps `window.WebSocket` and re-fires T3's thread events as `window` events. `turnlogic.js` (pure, shared rules) turns those events into a view; `turnbox.js` draws it above the composer. One JSON file of test cases is checked by both the Python and the JS tests, so the two sides keep the same rules.

**Tech Stack:** Python 3.12 standard library (`unittest`), vanilla browser JS, Node's built-in `node --test` for JS tests. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-22-turn-box-design.md` (read it first, including "Decisions from the builder check").

## Review Focus

1. A thread with no `update_plan`/`wrap_up` calls at all (most chats, and every non-profile chat): nothing is drawn, no errors in the console. → Task 2 test `empty items give empty view`.
2. Switching chats while a box is showing: the box belongs to the chat it came from and must not appear in another chat. → Task 4 keeps state per thread id; Task 2 test `views are per thread`.
3. A `wrap_up` whose buttons are all invalid (e.g. label `/commit`): no buttons drawn, and with an `ask` but no valid button and not blocked, no box at all. → shared case `all buttons invalid, no box`.
4. Claude calls `advance` with no plan in memory (after a restart): server changes nothing and asks for `items`. → Task 1 test `advance without plan asks for items`.
5. The page reloads mid-chat: the box or interrupted list comes back from the HTTP snapshot, and if that fails from the helper. → Task 4 manual check; Task 5 test `turn fallback returns calls after last user text`.

### Task 2: Shared turn logic in JS

**Files:**
- Create: `turnlogic.js`, `tests/turnlogic.test.js`

**Interfaces:**
- Consumes: `tests/turn_cases.json` (Task 1).
- Produces `turnlogic.js`, a plain script that sets `globalThis.OlympusTurn = {normalizeWrapUp, showsBox, applyPlan, view}` and also `module.exports` the same object when `module` exists:
  - `normalizeWrapUp(input) -> card` and `showsBox(card) -> bool`, `applyPlan(steps|null, args) -> steps|null` (same rules as Task 1; no result text).
  - `view(items, run) -> {plan: {steps, old: bool, live: bool}|null, box: {id, recap, ask, blocked, actions}|null}`. `items`: the thread's turn items in order (`{id, type, toolName, input, status, ordinal}`, types as T3 sends them: `user_message`, `dynamic_tool`, …). `run`: `{status}` of the latest run (`running`, `waiting`, `completed`, or other end states) or null. Rules = spec "Decisions" point 2: ignore `dynamic_tool` items with `status` `failed`/`error`; the plan is rebuilt by folding `applyPlan` over `__update_plan` inputs; a `__wrap_up` after the plan marks every step completed; `old` = the plan's last call is before the latest `user_message`; `live` = run status is `running` or `waiting`. Box only when the run is not live, the latest `__wrap_up` comes after the latest `user_message`, and `showsBox` holds. Plan shown when: live and (not old, or old with unfinished steps); or not live, no box, and it has unfinished steps.

- [ ] **Step 1: Write `tests/turnlogic.test.js`** (`node:test`, `node:assert`, `require("../turnlogic.js")`): every case in `turn_cases.json`; plus `empty items give empty view` (→ `{plan:null, box:null}`); `box after turn ends`; `no box while running`; `box cleared by user reply`; `old finished plan hidden`; `old unfinished plan shown as old`; `interrupted turn keeps list`; `failed calls ignored`; `views are per thread` (two `view` calls on different item lists don't share state, i.e. `view` is pure).

### Task 3: Socket hook and patch changes

**Files:**
- Create: `olympus-hook.js`, `tests/hook.test.js`, `tests/test_patch.py`
- Modify: `patch.py` (`files()`, new `refresh()`, `restore()` list), `launch.pyw`

**Interfaces:**
- Produces: `window` CustomEvent `"olympus:thread"` with `detail = {threadId, kind: "item"|"run"|"snapshot", payload}`. `item` payload = a turn item (from `turn-item.updated`); `run` payload = the `run.updated` event payload (has `status`, `ordinal`, `threadId`); `snapshot` payload = the subscription snapshot's `projection`.
- Produces in `olympus-hook.js`: a pure `parseFrame(data, subs) -> [{threadId, kind, payload}]` (handles string or ArrayBuffer, single message or array; `subs` = Map requestId→threadId), exported via `module.exports` when present, so `tests/hook.test.js` can test it. The browser part wraps `window.WebSocket` only for URLs whose path ends in `/ws`, records `orchestration.subscribeThread` request ids from `send`, and dispatches events. It must never throw into T3's code (wrap in try/catch).
- Produces in `patch.py`: `files()` returns the same three names; `index.html` gets `<script>` + the hook source inlined **immediately before** T3's first `<script type="module"`; `olympus.js` = olympus.js (gods filled) + `cards.js`, `turnlogic.js`, `turnbox.js`, `panel.js` (no `nextstep.js`). `refresh() -> bool` rewrites stale unpacked files when `is_unpacked()` is already true (works with T3 open), returns whether it wrote anything.
